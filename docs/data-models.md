# Data Models — FinTrust AI

Complete database schema, model fields, and relationships.

---

## Entity Relationship Overview

```
User (users)
 ├── Transaction (transactions)  [FK: user]
 │    └── FraudAlert (fraud_alerts)  [OneToOne: transaction]
 └── RiskProfile (risk_profiles)  [FK: user]
```

---

## User

**Table:** `users`  
**Model:** `apps.users.models.User`  
**Inherits:** `AbstractBaseUser`, `PermissionsMixin`

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | UUID | PK, auto | Generated by `uuid4` |
| `full_name` | CharField(100) | Required | Display name |
| `email` | EmailField | Unique, Required | Used as `USERNAME_FIELD` |
| `role` | CharField(20) | Choices | `analyst` (default) or `admin` |
| `is_active` | BooleanField | Default: True | Account status |
| `is_staff` | BooleanField | Default: False | Django admin access |
| `created_at` | DateTimeField | Auto | Set on creation |

**Authentication:** Email + password. JWT tokens issued on login.

**Roles:**

| Role | Permissions |
|------|-------------|
| `analyst` | CRUD on own transactions, own risk profile, own alerts |
| `admin` | Full access to all records, all analytics, all users |

## Transaction

**Table:** `transactions`  
**Model:** `apps.transactions.models.Transaction`

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | UUID | PK, auto | Generated by `uuid4` |
| `user` | FK → User | CASCADE, required | Transaction owner |
| `amount` | DecimalField(12,2) | Required | In XAF |
| `type` | CharField(20) | Choices, required | See below |
| `payment_method` | CharField(30) | Choices, default: `mobile_money` | See below |
| `location` | CharField(100) | Default: `Yaoundé` | City or region |
| `timestamp` | DateTimeField | Default: now | When transaction occurred |
| `device_change` | BooleanField | Default: False | New device detected — fraud signal |

**Type choices:**

| Value | Label | Description |
|-------|-------|-------------|
| `credit` | Credit | Money received |
| `debit` | Debit | Money spent |
| `transfer` | Transfer | Money sent to another account |

**Payment method choices:**

| Value | Label |
|-------|-------|
| `mobile_money` | Mobile Money (MTN MoMo, Orange Money, etc.) |
| `bank` | Bank Transfer |
| `cash` | Cash |

**Default ordering:** `-timestamp` (newest first)

## FraudAlert

**Table:** `fraud_alerts`  
**Model:** `apps.fraud_detection.models.FraudAlert`

Each alert is linked 1:1 to a `Transaction`. Running `/fraud/analyze/` with a `transaction_id` creates or updates the alert (`update_or_create`).

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | UUID | PK, auto | Generated by `uuid4` |
| `transaction` | OneToOneField → Transaction | CASCADE | The analyzed transaction |
| `fraud_probability` | IntegerField | 0–100 | 0 = safe, 100 = certain fraud |
| `urgency` | CharField(10) | Choices | See below |
| `explanation` | TextField | Blank allowed | AI explanation text |
| `indicators` | JSONField | Default: `[]` | List of specific risk factors |
| `action` | CharField(10) | Choices | Recommended action |
| `created_at` | DateTimeField | Auto | Alert creation time |

**Urgency choices:**

| Value | Threshold |
|-------|-----------|
| `LOW` | < 30% fraud probability |
| `MEDIUM` | 30–60% |
| `HIGH` | 60–80% |
| `CRITICAL` | > 80% |

**Action choices:**

| Value | Meaning |
|-------|---------|
| `ALLOW` | Transaction looks normal, proceed |
| `FLAG` | Suspicious — flag for manual review |
| `BLOCK` | High confidence fraud — block transaction |

**Default ordering:** `-created_at`

## RiskProfile

**Table:** `risk_profiles`  
**Model:** `apps.credit_scoring.models.RiskProfile`

Created each time `/credit-score/analyze/` is called with a `user_id`. A user can have multiple risk profiles over time; the most recent is used for display.

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| `id` | UUID | PK, auto | Generated by `uuid4` |
| `user` | FK → User | CASCADE | Profile owner |
| `risk_score` | IntegerField | 0–100 | 0 = high risk, 100 = very safe |
| `repayment_probability` | FloatField | 0.0–1.0 | Probability of on-time repayment |
| `recommended_loan` | DecimalField(12,2) | Default: 0 | Max recommended loan in XAF |
| `ai_summary` | TextField | Blank allowed | AI explanation text |
| `created_at` | DateTimeField | Auto | When this assessment was made |

**Risk score bands:**

| Band | Score Range | Color |
|------|-------------|-------|
| High Risk | 0–39 | 🔴 `#EF4444` |
| Medium Risk | 40–69 | 🟡 `#F59E0B` |
| Low Risk | 70–100 | 🟢 `#22C55E` |

**Default ordering:** `-created_at`

## Migrations

Migrations are managed per app under `apps/<app>/migrations/`. To run all migrations:

```bash
python manage.py migrate
```

To create migrations after model changes:

```bash
python manage.py makemigrations
```

## Seeding Demo Data

```bash
python manage.py seed_demo
```

This command creates:
- 1 admin user + 4 analyst users
- ~80 transactions spread across users with realistic amounts and locations
- Risk profiles for each user with pre-set scores
- Several fraud alerts at various urgency levels

The seed command is idempotent — running it multiple times won't create duplicates (it uses `get_or_create` for users).

## Database Indexes

Primary keys are UUID on all models. Consider adding the following indexes for production performance:

```python
# In RiskProfile.Meta
indexes = [
    models.Index(fields=['user', '-created_at']),
    models.Index(fields=['risk_score']),
]

# In Transaction.Meta
indexes = [
    models.Index(fields=['user', '-timestamp']),
    models.Index(fields=['type']),
]

# In FraudAlert.Meta
indexes = [
    models.Index(fields=['urgency', 'action']),
    models.Index(fields=['-created_at']),
]
```
